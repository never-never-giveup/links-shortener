# Skill: Knowledge Base

## Цель

Держать `knowledge-base/` синхронной с кодом. После каждой задачи, что-то
менявшей в `app/`, `tests/`, `alembic/`, `pyproject.toml`, `docker-compose.yml`
или `.agents/`, проверять — не устарели ли страницы вики, не закрыт ли пробел,
не появилась ли новая сущность/контракт. Источник правил —
`knowledge-base/AGENTS.md` (метод LLM Wiki: заземлённые факты + пробелы).

> Скилл не заменяет code review и не запускается отдельной задачей. Это
> финальный шаг в `feature` / `bugfix` / `refactoring` / `hotfix` / `docs`
> **после** зелёных проверок и **до** коммита: правки базы знаний идут в тот
> же коммит, что и код.

***

## Когда запускать (триггеры filing back)

Запусти актуализацию, если в задаче произошло **что-то из**:

- Добавлен/изменён/удалён эндпоинт, маршрут, DTO, публичный метод сервиса.
- Добавлена/изменена доменная сущность, value object, доменная ошибка.
- Изменена схема БД: новое поле, индекс, миграция.
- Изменён ENV, переменная конфигурации, команда запуска, зависимость в
  `pyproject.toml`.
- Переименовано что-то, на что ссылается вики (функция, класс, файл, тест).
- Найден и закрыт ранее зафиксированный пробел `G<N>` из `wiki/decisions.md`.
- Появился новый устоявшийся факт (не гипотеза), которого в вики нет.
- Изменился внешний первоисточник (вышла новая мажорная версия FastAPI /
  SQLAlchemy / Alembic, изменился conventional-commits spec).

Если ничего из этого не произошло — шаг пропускается. Не делай правки «для
галочки»: лишние правки разводят шум в `LOG.md` и мешают отслеживать реальные
события.

***

## Алгоритм

### 1. Прочитать карту и решить, что менять

```bash
# Карта вики — какие страницы существуют
cat knowledge-base/INDEX.md
# Журнал — что уже зафиксировано, чтобы не дублировать
cat knowledge-base/LOG.md
```

Определи по `INDEX.md`, какие страницы затронуты. Если сомневаешься — открой
`wiki/decisions.md` и релевантную страницу целиком, сверь с текущим кодом.

### 2. Обновить страницы `wiki/`

Каждый нетривиальный факт в `wiki/` обязан иметь подтверждение
(`knowledge-base/AGENTS.md:72-85`):

- **Внутренний факт** → `file:line` + имя функции/класса/маршрута/теста.
  Пример: «TTL ограничен 86400 — `app/api/schemas.py:7` `MAX_TTL_SECONDS`,
  тест `test_post_link_ttl_over_max_returns_422`».
- **Внешний факт** → ссылка на карточку в `raw/` (URL + дата проверки).
  Пример формата: `[raw/sqlalchemy.md](raw/sqlalchemy.md)` — где `raw/sqlalchemy.md`
  содержит URL `docs.sqlalchemy.org` и дату проверки.

Правила правки:

- Меняешь `file:line` — открой файл и **проверь** что строка/имя всё ещё
  актуальны. Не угадывай по памяти.
- Если код, на который ссылалась вики, удалён/переименован — обнови ссылку
  или переведи факт в пробел (если новое место неизвестно).
- Не дублируй: одна тема = одна страница. Второе упоминание — ссылкой на
  каноничное место.
- Все правки — на русском (см. таблицу «Язык общения» в `.agents/AGENTS.md`).

### 3. Закрыть/открыть пробелы

- **Закрылся пробел `G<N>`** — удали его из `wiki/decisions.md` (секция
  `## Пробелы`) и из секции `## Пробелы` на затронутой странице, если он там
  упоминался. На его место в `decisions.md` ничего не сдвигай — нумерация `G<N>`
  не перенумеруется, идентификаторы стабильны (как у ADR). Если позже появится
  новый пробел — он получит следующий свободный номер.
- **Нашёлся новый пробел** — добавь `G<N+1>` в `wiki/decisions.md` и секцию
  `## Пробелы` на релевантной странице. Пробел = факт, который **не удалось
  подтвердить** кодом/тестом/документацией. Не додумывай.

### 4. Обновить `INDEX.md` (если состав страниц изменился)

Только если появилась новая страница `wiki/` или исчезла существующая.
Правки `file:line` внутри существующих страниц `INDEX.md` не трогают — там
только список страниц с кратким описанием.

### 5. Прогнать lint (целостность базы знаний)

Обязательные проверки перед коммитом — `knowledge-base/AGENTS.md:134-153`:

```bash
# 1. Битые ссылки — все Markdown-ссылки должны указывать на существующие файлы.
#    Извлекает пути ](...) и проверяет их существование относительно текущей страницы.
rg --no-line-number -o '\]\(([^)]+)\)' knowledge-base/ -r '$1' \
  | grep -v '^http' \
  | sort -u
# Вручную проверь каждый выведенный путь: существует ли файл/якорь.
# Для сквозной автоматической проверки можно использовать mdformat:
# uv run --with mdformat mdformat --check knowledge-base/

# 2. Сиротские страницы — каждая страница wiki/ достижима из INDEX.md
rg -l 'wiki/' knowledge-base/INDEX.md

# 3. Дубли — одна тема = одна страница. Проверить глазами по INDEX.md.
```

Линтер ловит пять классов проблем (полный список —
`knowledge-base/AGENTS.md:134-148`): битые ссылки, сиротские страницы, дубли,
противоречия, устаревшие сведения, пробелы без идентификатора `G<N>`.

### 6. Дописать событие в `LOG.md`

Append-only, новая запись **сверху** (свежее событие — первым). Формат:

```
- ГГГГ-ММ-ДД | <тип> | <что> | <где> | <контекст>
```

Типы событий: `ingest`, `update`, `gap-found`, `gap-closed`, `link-fix`,
`lint`. Примеры:

```
- 2026-09-03 | update | Обновлены ссылки file:line на routes.py после добавления PATCH /links/{id} | wiki/contracts/http-api.md | задача PROJ-123
- 2026-09-03 | gap-closed | G5 закрыт — добавлен retry при коллизии кода | wiki/decisions.md, wiki/domain/links.md | задача PROJ-140
- 2026-09-03 | gap-found | G9 — нет rate-limit на POST /links | wiki/decisions.md | code review PROJ-150
```

### 7. Нет триггеров — пропусти

Если ни один триггер из списка выше не сработал — шаг пропускается полностью,
запись в `LOG.md` не добавляется. Не генерируй шум.

***

## Итоговый блок в отчёте задачи

Если шаг выполнялся — добавь в стандартный отчёт строку:

```
KB: <какие страницы обновлены / какой пробел закрыт>
```

Если пропущен — строку не добавляй.

***

## Пример промпта

~~~text
Фича PROJ-123: добавлен эндпоинт PATCH /links/{id} (app/api/routes.py:55
update_link). Тесты зелёные, ruff/basedpyright/pytest прошли. Перед коммитом
актуализируй базу знаний по скиллу .agents/skills/knowledge-base.md:

1. Прочитай knowledge-base/INDEX.md и wiki/contracts/http-api.md.
2. Добавь строку в таблицу маршрутов с заземлением file:line.
3. Если в decisions.md есть пробел про PATCH — закрой (удали G<N>).
4. Прогон lint по чеклисту из knowledge-base/AGENTS.md.
5. Допиши запись в LOG.md сверху.
~~~
