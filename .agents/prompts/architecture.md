# Архитектурный документ

Промт для написания архитектурного плана **до** начала реализации.

---

## Вариант A — субмодуль в проекте (`.agents/`)

```text
Jira: <JIRA-KEY>
Задача: <описание одной строкой>

Прочитай .agents/AGENTS.md, .agents/agents/architecture.md, .agents/skills/architecture.md.

Изучи кодовую базу проекта: структуру репозитория, существующие сервисы,
базовые классы и паттерны (Strategy, Repository, Service и т.п.), Settings,
точки расширения.

Напиши архитектурный документ по алгоритму из .agents/skills/architecture.md:

1. Контекст и цель — что именно меняется, DoD одной фразой.
2. Ограничения — лимиты, форматы, SLA, безопасность.
3. Затронутые репозитории — явно перечисли все.
4. C1-диаграмма (Context) — система + пользователь + внешние системы, Mermaid.
5. C2-диаграмма (Container) — сервисы, хранилища, очереди, Mermaid.
6. Компонентная модель — таблица: существующее / новое / изменяется.
7. Архитектурные решения — пронумерованный список с альтернативами и trade-offs.
8. Data contracts — только дельта: новые/изменённые Pydantic-модели, API, Kafka.
9. Список файлов — таблица: репозиторий / файл / действие / что меняется.
10. Задачи T1–TN — каждая ≤ 1 день, с точными путями, контрактом и DoD-командами.
11. Риски — таблица 🔴🟡🟢.

Сохрани в Tasks/<JIRA-KEY>/<JIRA-KEY>-architecture.md.
Если нашёл противоречие или недостающую информацию — спроси, не додумывай.
```
