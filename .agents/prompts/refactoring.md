# Рефакторинг

Поведение не меняется. Только структура кода.

---

## Вариант A — субмодуль в проекте (`.agents/`)

```text
Jira: <JIRA-KEY>
Рефакторинг: <что и зачем меняем>

Прочитай .agents/AGENTS.md, .agents/agents/docs.md,
.agents/skills/refactoring.md и .agents/skills/docs.md.

Создай ветку с именем РОВНО `refactor/<JIRA-KEY>-<slug>`.

Ограничения рефакторинга:
- Поведение не меняется ни на йоту — те же входы, те же выходы.
- Public API не меняется — сигнатуры остаются.
- Никаких миграций БД — это чистый рефакторинг кода.
- Существующие тесты остаются зелёными без правок.
  Если тест сломался — ты случайно изменил поведение, остановись.

Сделай:
1. <конкретное действие 1>
2. <конкретное действие 2>
3. Юнит-тесты для новых публичных единиц (если появились).

После каждого изменения:
uv run ruff check .
uv run basedpyright
uv run pytest -q

Документация (по .agents/skills/docs.md):
- ADR если решение архитектурное.
- Запись в CHANGELOG.md → Changed.
- Обнови docstring если изменилось расположение/ответственность.
```
